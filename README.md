# qSHA256

**What would it actually cost a quantum computer to compute SHA-256?**

qSHA256 builds SHA-256 out of reversible quantum circuits, executes them to prove
they are correct, measures what they cost, and searches for cheaper ones.

The usual answer to "how does SHA-256 fare against quantum computers" is `2^128`
— Grover's query count for a 256-bit preimage. That number says nothing about
what a query *costs*. This project builds the circuit underneath it: the qubits,
the reversible arithmetic, the ancillas, the uncomputation, the Toffoli and T
counts, and the two-full-SHA-256-evaluations that one Grover query actually is.

[![CI](https://github.com/icedmoca/qSHA256/actions/workflows/ci.yml/badge.svg)](https://github.com/icedmoca/qSHA256/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](LICENSE)

> **This is a research and educational project, not a cryptography library.**
> It does not hash anything faster than `hashlib`, provides no security
> guarantees, and has never run on quantum hardware. It does not break SHA-256
> and finds no weakness in it.

---

## The headline result

A reversible circuit for the **full 64-round, 32-bit SHA-256 compression
function** is constructed, executed, and verified against `hashlib`:

```
$ qsha256 validate
...
Layer 4 - full 64-round SHA-256
  [PASS] sha256 compression, 64 rounds, forward == classical
  [PASS] sha256 compression, 64 rounds, garbage-free == classical
  [PASS] 32-bit 64-round circuit digest == hashlib.sha256(b'abc')
...
15/15 checks passed, 4,721 cases
```

This is not a scaled-down proxy. Every SHA-256 compute circuit here is a
*permutation* circuit — only X, CNOT and Toffoli — so it can be executed exactly
on computational basis states in time linear in the gate count, no statevector
required. A 1,057-qubit circuit that no simulator on Earth could handle in
superposition runs in under a second on basis states, and produces
`ba7816bf...15ad` for `b"abc"`.

## Current resource results

All figures **measured** from constructed circuits and regenerated by
`python scripts/generate_benchmarks.py`. Full tables:
[`benchmarks/results/latest.md`](benchmarks/results/latest.md).

### Scaling with round count

Default architecture (CDKM adder, rolling schedule, serial round layout),
forward evaluation only:

| Rounds | Qubits | Gates | Toffoli | Depth | T-count |
|---:|---:|---:|---:|---:|---:|
| 1 | 1,057 | 4,186 | 1,088 | 2,426 | 7,616 |
| 2 | 1,057 | 6,582 | 1,664 | 3,566 | 11,648 |
| 4 | 1,057 | 11,398 | 2,816 | 5,846 | 19,712 |
| 8 | 1,057 | 20,998 | 5,120 | 10,406 | 35,840 |
| 16 | 1,057 | 40,194 | 9,728 | 19,526 | 68,096 |
| 32 | 1,057 | 93,528 | 22,016 | 45,558 | 154,112 |
| **64** | **1,057** | **200,162** | **46,592** | **97,622** | **326,144** |

T-counts are measured from a circuit actually transpiled into Clifford+T, and
match the analytical `7 x Toffoli` model exactly — which anchors the model to a
real compiler.

The cost is not linear in rounds: the message schedule does not begin expanding
until round 16, because rounds 0–15 consume the message block directly.

### The three circuits that matter

| Circuit | Qubits | Toffoli | T-count | Depth |
|---|---:|---:|---:|---:|
| forward compression | 1,057 | 46,592 | 326,144 | 97,622 |
| garbage-free (uncomputed) | 1,313 | 92,672 | 648,704 | 193,874 |
| **preimage oracle** | **1,535** | **94,202** | **659,414** | **195,280** |

**One Grover query costs 2.02x a forward SHA-256 evaluation** — measured, not
assumed. It is a garbage-free forward hash, a 256-bit digest comparison, and a
full inverse hash.

### Where the cost goes

| Component | Toffoli | % |
|---|---:|---:|
| `T1` accumulation | 20,480 | 44.0% |
| `T2` accumulation | 12,288 | 26.4% |
| message schedule | 9,216 | 19.8% |
| `d += T1` | 4,096 | 8.8% |
| chaining addition | 512 | 1.1% |
| `H` -> working copy | 0 | 0.0% |

Components are disjoint and sum exactly to the circuit total. Modular addition
dominates; the sigma functions cost **zero Toffolis** because rotations and
shifts are wire relabellings, not gates.

## Comparison with published work

Against Amy, Di Matteo, Gheorghiu, Mosca, Parent & Schanck (SAC 2016,
[arXiv:1603.09383](https://arxiv.org/abs/1603.09383)), Table 1 — transcribed with
per-metric comparability verdicts so a Toffoli-level depth is never silently
divided by a Clifford+T depth.

| Metric | qSHA256 | Amy et al. (pre-T-par) | | Amy et al. (T-par) | |
|---|---:|---:|---|---:|---|
| logical qubits | 1,057 | 2,402 | **56% fewer** | 2,402 | **56% fewer** |
| T-count | 326,144 | 401,584 | **19% fewer** | 228,992 | *42% more* |
| T-depth | 154,112 | 171,552 | **10% lower** | 70,400 | *119% more* |
| depth | 463,606 | 528,768 | 12% lower | 830,720 | 44% lower |

**Where we win:** substantially fewer qubits, from the in-place rolling message
schedule and a round layout that allocates no permanent qubits.

**Where we lose:** T-par is a phase-polynomial optimizer that merges T gates
across gate boundaries; qSHA256 does no cross-gate T optimization, so its T-count
stays at exactly `7 x` its Toffoli count. That gap is real and
[documented](docs/leaderboard.md), not hidden.

## Automated design search

qSHA256 does not ship one circuit. It ships a space of provably-correct circuits
and searches it.

```bash
qsha256 search --spec toy4 --rounds 8
```

```text
104 designs evaluated; 7 on the Pareto front over qubits, t_count, toffoli_depth

cdkm/load/rolling/serial/rewritten:      t_count -20.7%, toffoli_depth -24.4%
cdkm/vbe_const/rolling/wide/rewritten:   t_count -20.7%, toffoli_depth -38.5%
                                             at the cost of qubits +17.6%
qft/load/rolling/wide:                   toffoli_depth -97.4%
                                             at the cost of t_count +10627.0%
```

Every design is functionally verified against the classical reference before its
numbers are allowed into a report. All 96 basis-simulable designs pass; the 8
QFT-adder designs are labelled `UNSUPPORTED` rather than silently trusted.

Three findings worth stating:

- **The `wide` round layout cuts depth 25% at identical T-count**, for 128 extra
  qubits. The best trade in the space.
- **The QFT adder is a trap.** It has by far the fewest Toffolis (8,192 vs
  46,592) and by far the worst T-count (301 million), because arbitrary-angle
  rotations must be synthesised from Clifford+T. A Toffoli count is not a
  fault-tolerant cost.
- **Carry-save addition loses.** On paper it should win — three constant-depth
  CSA layers beat four ripple adders. Reversible uncomputation doubles the tree
  and it comes out worse: 58,496 Toffolis against 46,592. A negative result,
  reported as one.

The gate-level rewriter also **rediscovers a human optimization**: constant
folding specialises the generic adder in `const_add="load"` down to exactly the
circuit that `const_add="vbe_const"` hard-codes by hand. Both converge to the
same Toffoli count, and that is asserted as a test.

## Grover, without the hype

```bash
qsha256 grover-demo     # actually runs, on a toy
qsha256 oracle          # full-scale oracle cost + extrapolation
```

The toy demo executes real amplitude amplification on a ~15-qubit reduced hash,
raising a planted solution from probability 0.0625 to **0.9613**. It is labelled
a toy everywhere it appears.

For real SHA-256, the oracle is *constructed and measured*, then combined with
the analytic query count and labelled `EXTRAPOLATED`. Nothing is simulated.

Three things the plain `2^128` story omits, all of which the reports state:

1. **A query is not a hash evaluation** — measured at 2.02x here.
2. **Grover barely parallelises.** `m` machines buy `sqrt(m)`, not `m`.
3. **Depth limits bite.** `2^128` iterations is inherently serial, which is why
   NIST evaluates such attacks under an explicit `MAXDEPTH` cap.

See [`docs/grover.md`](docs/grover.md).

## Install and use

```bash
git clone https://github.com/icedmoca/qSHA256.git
cd qSHA256
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

qsha256 validate                     # verify circuits against the classical model
qsha256 analyze --rounds 64          # measure logical resources
qsha256 benchmark                    # scaling table
qsha256 search --spec toy4           # Pareto search over the design space
qsha256 oracle                       # preimage oracle + Grover extrapolation
qsha256 physical --model optimistic  # fault-tolerant estimate
qsha256 leaderboard                  # compare against published circuits
qsha256 grover-demo                  # run the toy Grover search
```

As a library:

```python
from qsha256 import SHA256
from qsha256.quantum.sha256.compression import build_compression
from qsha256.quantum.resources import analyze

comp = build_compression(SHA256, rounds=64)
print(analyze(comp, spec=SHA256, rounds=64))
```

## How the numbers are labelled

Every figure carries its provenance, because "SHA-256 needs N T gates" means
something different under each:

| Label | Meaning |
|---|---|
| `MEASURED` | counted off a constructed circuit |
| `TRANSPILED` | measured after a compiler rewrote it into Clifford+T |
| `ANALYTICAL` | derived from measured counts via a documented model |
| `EXTRAPOLATED` | projected beyond what was built, with the rule shown |
| `ASSUMPTION-DEPENDENT` | needs a hardware/error-correction model to mean anything |

qSHA256 never equates logical with physical qubits, never equates circuit
construction with execution, and never presents a compiler-dependent number as a
physical constant. There is no single "T-count of a Toffoli" — there are
[three documented models](docs/resource-metrics.md), and every report says which
one it used.

## Limitations, briefly

Nothing has run on quantum hardware. Full-scale SHA-256 has never been simulated
in superposition, only on basis states. Grover has never been run against real
SHA-256. The T-count carries no phase-polynomial optimization. Depth assumes
all-to-all connectivity with no routing overhead. Multi-block hashing is chained
classically. Read [`docs/limitations.md`](docs/limitations.md) before quoting
anything.
