# SHA-256, in the detail a circuit needs

A compact reference for the structure qSHA256 implements. The normative
definition is [FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf).

## Overall shape

```text
message
  |  pad to a multiple of 512 bits
  v
512-bit blocks
  |  for each block:
  v
message schedule: 16 words -> 64 words
  |
  v
64 compression rounds over 8 working words
  |
  v
add the working words into the chaining state
  |
  v
256-bit digest
```

## Padding (section 5.1.1)

Append `0x80`, then zero bytes, then the 64-bit big-endian message length in
bits, so the total is a multiple of 64 bytes. The boundary cases (55, 56 and 64
byte messages) are where hand-written implementations usually break, and are
tested explicitly.

Padding is *classical*: the message length is public, so in a quantum circuit the
padding bits are loaded with X gates rather than occupying input qubits. That is
a real saving, and `build_compression(message_constants=...)` exposes it.

## Constants

`K[0..63]` are the first 32 fractional bits of the cube roots of the first 64
primes; `H[0..7]` the first 32 fractional bits of the square roots of the first 8
primes.

qSHA256 **derives** these rather than transcribing them
(`qsha256/spec.py:frac_bits_of_root`), using exact integer arithmetic - double
precision is not accurate enough - and the test suite checks the derivation
against the published tables. This matters because the same rule generates the
constants for the reduced toy specs.

## Message schedule

```text
W[t] = M[t]                                             for t = 0..15
W[t] = sigma1(W[t-2]) + W[t-7] + sigma0(W[t-15]) + W[t-16]   for t = 16..63
```

## Round function

```text
T1 = h + Sigma1(e) + Ch(e,f,g) + K[t] + W[t]
T2 = Sigma0(a) + Maj(a,b,c)

h = g;  g = f;  f = e;  e = d + T1
d = c;  c = b;  b = a;  a = T1 + T2
```

Six of the eight assignments are pure renaming. Only `a` and `e` are computed,
and both are computed by *adding into* a register that is about to be discarded.
That observation is what makes the reversible round allocate no permanent qubits
at all - see `docs/quantum-architecture.md`.

## Functions

```text
Ch(x,y,z)     = (x AND y) XOR ((NOT x) AND z)
Maj(x,y,z)    = (x AND y) XOR (x AND z) XOR (y AND z)

Sigma0(x) = ROTR^2(x)  XOR ROTR^13(x) XOR ROTR^22(x)
Sigma1(x) = ROTR^6(x)  XOR ROTR^11(x) XOR ROTR^25(x)
sigma0(x) = ROTR^7(x)  XOR ROTR^18(x) XOR SHR^3(x)
sigma1(x) = ROTR^17(x) XOR ROTR^19(x) XOR SHR^10(x)
```

`Ch` is a bitwise multiplexer: it selects `y` where `x` is 1 and `z` where `x` is
0. `Maj` is bitwise majority. Both facts are asserted in the test suite, because
they are the intuitions the reversible rewrites rest on.

## Arithmetic

Every `+` above is modulo 2^32. In a reversible circuit that reduction is free:
you build an adder and simply never compute the carry out of the top bit.
Discarding the carry *is* the reduction.

## The reduced models

`toy4` and `toy8` share every code path with `sha256`, at 4- and 8-bit word
widths. They exist so that circuits can be checked exhaustively rather than by
sampling. They are **not SHA-256** and are never described as such; their
rotation amounts are reduced modulo the word size and their constants come from
the same prime-root rule at the smaller width.
